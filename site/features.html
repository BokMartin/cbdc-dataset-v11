The questions we answer for every project

One project, ten coded cells. Each cell is a question answered only from the project's own official documents under the measurement contract v1.1, and each answer carries five things: the value, an evidence state (documented / partial / unknown / conflict), a commitment status (option / adopted / tested / operational), the decisive document, page and verbatim quote, and the date. Absence of mention is unknown, never no.

What counts as evidence

The authority layer of a document decides what a value can be.

Official decisionBoard decision, law, final report of the competent body. Can set adopted / operational. Later decision on the same matter supersedes an earlier one.
Official design documentConsultation paper, design note, white paper, progress update. Sets a value with status option unless the body presents it as a commitment ("if issued, the central bank will not…").
Pilot / PoC reportExperiment reports, pilot evaluations. Set a value with status tested; a tested capability is never an adopted commitment.
Staff researchWorking papers with an author-views disclaimer. Flagged separately; may corroborate a value, never establishes one. Background law published before 2018 is used only for the legal basis of F3.

Inference is allowed only as a necessary conclusion from documented premises, with the premises recorded and the cell flagged inferred: F2 = yes needs three documented premises (the PSP holds an identifier → person mapping, routinely sees the transaction record, and can link the two); F7 = no may be inferred only when verified onboarding is documented and no document mentions any lower-identification route. Conflicts between two adopted claims of equal standing are stored as conflict and adjudicated by the authors, never by a model.

Layer 1 — the six architecture categories

Three cells decide the type. Online axis: A = the central bank or core operator can routinely link an online payment to a person (F1 yes); B = it cannot, but the user's payment service provider can (F1 no, F2 yes); C = neither can (F1 no, F2 no). Offline axis: 0 = no adopted private offline mode (F4 no); 1 = adopted (F4 yes). A missing input gives a partial type (B?, B/C0). The type is nominal — never a score, never coded 1–6, never correlated.

Layer 2 — declared objectives

F11 records which objectives the institution declares, each flag with a quote, and whether it ranked one as primary (one_primary / several_joint / unranked / conflict). The six flags are payment modernisation, financial inclusion, monetary sovereignty & transmission, cash substitute & resilience, AML/CFT/tax enforcement, innovation & competitiveness. A zero flag means "not documented", not absence of motive; "the CBDC will comply with AML rules" is a design requirement, not an objective. Word frequencies never set a flag. The map's objective mode shows the primary objective where one is ranked, otherwise "several, jointly" or "declared, unranked".

Outcomes used in the empirical illustration

Y₁ = 1 if F1 = no (adopted): the central bank is separated from transaction identity. Primary illustration, used only if ≥ 20 projects are determinable and the minority class has ≥ 6. Y₃ = 1 if F7 = yes; reported with and without inferred zeros. Y₂ (public-authority access) was dropped in v1.1: F3 is kept as a descriptive route, because the routine-vs-targeted distinction depends on law outside the corpus. Hypotheses, estimand (Δ between predictor quartiles) and the smallest effect of interest are in PREDICTIONS v2.2.
