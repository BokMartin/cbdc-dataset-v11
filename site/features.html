The questions we answer for every project

Each cell is one question answered from the project's own official documents. A cell carries a value, an evidence state (documented / partial / unknown / conflict), a commitment status (option / adopted / tested / operational), the decisive document and page, and a verbatim quote. The full definitions are the measurement contract v1.1; the table is parsed from it.

Layer 1 — architecture type

Three cells decide the type. Online axis: A = the central bank can routinely link an online payment to a person (F1 yes); B = it cannot, but the user's payment service provider can (F1 no, F2 yes); C = neither can (F1 no, F2 no). Offline axis: 0 = no adopted private offline mode (F4 no); 1 = adopted (F4 yes). Missing input gives a partial type such as B?. The type is nominal — never a score.

Outcomes used in the empirical illustration

Y₁ = 1 if F1 = no (adopted): the central bank is separated from transaction identity. Primary illustration, used only if ≥ 20 projects are determinable and the minority class has ≥ 6. Y₃ = 1 if F7 = yes: a route to hold or pay up to a limit without verified identity exists; reported with and without inferred zeros. Y₂ (public-authority access) was dropped in v1.1: F3 is kept as a descriptive route only, because the routine-vs-targeted distinction depends on law outside the corpus. Hypotheses, estimands and the smallest effect of interest are in PREDICTIONS v2.2.
