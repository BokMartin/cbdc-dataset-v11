Who can see a CBDC payment — and what did the central bank actually commit to?

An open dataset of documented privacy and identifiability design in every retail central bank digital currency project with an official document. Each project is answered on ten design questions from its own documents — value, evidence, commitment status, quote, page, date — placed in one of six architecture categories, and tracked over time.

Why this dataset

Status trackers say a project is "piloting". They don't say who can see the payments.

Within a single tracker status, central banks commit to radically different designs: some keep transaction identity away from the central bank by construction, some see everything, some offer an offline mode with cash-like privacy and some rule it out. Press releases talk about privacy; design documents commit to it or don't. We read the official documents and code the commitments, not the vocabulary — and we record for every value the document, the page, the quote and whether it is an option under study, a tested capability, an adopted decision or a live arrangement.

Three things the data lets you do

1

Place every project in one of six architecture categories. Can the central bank link an online payment to a person? Can the user's provider? Is a private offline mode adopted? Those three answers give A0 … C1 — a nominal map of designs, not a score. How the categories are defined →

2

Watch designs change. Each value carries the year of its document, so the map can be read as of 2018, 2021 or today, and a project's path from option to commitment — or its reversal — is visible. Open the map and drag the year →

3

Separate what is declared from what is built. Declared objectives (inclusion, modernisation, sovereignty, resilience, enforcement, innovation) are recorded as non-exclusive flags with quotes and shown next to the architecture — so you can see, for example, which inclusion-declaring projects actually adopt a low-identification route.

How it is measured

A written measurement contract defines each cell, its allowed values and the traps a coder must avoid; absence of mention is unknown, never no; a staff paper never establishes a commitment. Values are extracted by a reproducible two-provider API pipeline with a mechanical check that every quote is on its cited page, verified by the authors on development projects, and audited against an independent human reference on a sealed test set. Hypotheses and the smallest effect of interest were registered before any cell was computed. The pipeline → · Method & progress →

Open by design

Data (CC BY 4.0), contract, pipeline code (MIT) and the validation record are public. Every cell can be challenged with a document and a page. How to contribute →
