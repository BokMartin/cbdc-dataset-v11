Pipeline

From an official PDF to a cell on the map: how a value is produced, logged, checked and audited. Everything on this page is runnable from the repository; the metrics shown are the targets the validation must meet.

Steps

1 · corpusRegistry of official documents391 documents, 92 registry codes, SHA-256 and source URL per row; three model passes + first author select the analytical core under a written rubric; an independent LLM audits and searches gaps. Frozen as core_v1 (dated additions as core_v2).
2 · textPage-delimited textpdftotext -layout, OCR for scans; one text file per document with page markers, so every quote can be located mechanically.
3 · contractMeasurement contractDefinitions, values, qualifiers, traps, inference and supersession rules. Versioned; frozen before production; registered.
4 · extractionAPI extraction, two providersextract_api.py: no chat history; either all documents of a project in one request or per-document findings → synthesis. Logs model id, SHA-256 of contract/prompt/script, raw responses, token usage.
5 · checkMechanical citation checkverify_quotes.py: is the quote on the cited page (±1)? The result travels with the cell as quote_verified; a quote not found voids the claim for audit.
6 · adjudicationModel–model disagreementCells where the two providers differ go to the authors with both justifications; the decision and its reasoning are logged. Agreements and empty cells are sampled and audited too.
7 · gateBlind human reference6–8 projects whose model output the authors never saw, coded independently by both authors from the PDFs. Scored once: α and AC1 (human–human, model–human), feature / type / Y error. Failure policy if tolerance is missed.
8 · releaseMatrix, claims, historymatrix.csv, claims.csv, history.json, types.csv, validation files; the site reads them directly.

Validation targets targets, not results

≥ 0.80
Krippendorff's α
human–human on the blind test set per family (0.667 provisional floor); AC1 reported alongside
≥ α − 0.05
model–human agreement
each provider against the human reference; disagreements adjudicated
≥ 95 %
quotes verified on page
development runs so far: 16–17 of 17 cells per project exact page; stage-1 findings 94–98 %
100 %
runs with manifest
model id, hashes, raw responses, usage — reproducible in intent; provider-side sampling is not settable

Development evidence to date (Norway, UK, contract v1.1): single-request and two-stage modes agree on all UK values but one; Norway differs on four cells, all traceable to one open definition (status of a design draft published with a decision not to issue). Those numbers are development material, not validation.

Reproduce

export ANTHROPIC_API_KEY=...            # or OPENAI_API_KEY with --provider openai
python3 scripts/extraction/extract_api.py --jur NO --model claude-opus-5-5 --mode both \
    --indir texts/NO --contract docs/MEASUREMENT_CONTRACT_v1_1_2026-10-18.md --outroot runs
python3 -I scripts/extraction/verify_quotes.py runs/<run>/FILL.csv texts/NO
python3 scripts/site/build_site_data.py       # rebuilds site/assets/data.json

Source: extract_api.py · verify_quotes.py · build_site_data.py. Interactive agent fills used during development are not instrument output and are labelled as such in the record.
