# Re-running the procedure from this repository

Goal (authors, 2 Nov 2026): everything the models are asked to do is kept here as versioned prompt text and runnable scripts, so that the machine part of the study can be re-run end to end by **any provider's API** from one clone, with the same inputs, and compared with the archived runs.

## What is here

- `PROMPTS.json` + `prompts/*.md`: every system prompt the pipeline sends, fully rendered from the contract and the schema, with SHA-256 hashes and the format of the user message for each stage. Regenerated by `scripts/pipeline/export_prompts.py`; `tests/test_prompt_export.py` fails if the files drift from the code. The hashes match the `system.sha256` recorded in every run manifest (e.g. `extraction_single.system` = `18f17658…` in the NO run of 2 Nov; `endorsement_census.system` = `dd472fa6…` in the census aggregate).
- `scripts/pipeline/run_all.py`: one command for the machine stages: frame → prompts → census → survey → extraction (single / two-stage / both) → citation check → mode comparison → website data. Each stage is an existing script with its own manifest and full request/response archive.

## Inputs you need

1. The PDFs listed in the registry (`data/registry/…`, with SHA-256), or the page-delimited texts made from them: `<texts>/<JUR>/DOCS.csv` + `texts/docNN.txt`, one `=== DOC n PAGE p ===` marker per page (`pdftotext -layout` per page; OCR with tesseract where a page has no text layer). The texts are not in the repository (copyright); the registry hashes let anyone verify they used the same files.
2. The contract and schema version you want to replay (`docs/MEASUREMENT_CONTRACT_*.md`, `schema/cells_*.json`).
3. An API key in the environment: `ANTHROPIC_API_KEY` or `OPENAI_API_KEY`. Provider differences are recorded in each manifest (Anthropic: temperature not settable, streaming; OpenAI: temperature 0).

## One-shot

```
python3 scripts/pipeline/run_all.py --provider anthropic --model claude-opus-5-5 \
  --texts /data/texts --sealed-dir /data/sealed \
  --contract archive/v11/docs/MEASUREMENT_CONTRACT_v1_1_2026-10-18.md --schema schema/cells_v1_1.json --mode both
```

`--dry-run` prints the commands without calling any API. `--projects NO,UK` limits the run. `--stages` selects stages.

## What is deliberately not one-shot

- **Human stages**: blind reference coding (`scripts/review/build_review_workbook.py reference`), adjudication, the blind draw, the δ elicitation and the release of sealed per-project results. They are documented in `METHOD.md`, `EXPOSURE_LEDGER.md` and `DECISIONS/`; their outputs are committed as data, never regenerated.
- **Sealed outputs**: the census and the statement survey write per-project results outside the repository; only aggregates and the sealed file's hash are committed. A fresh re-run produces a new sealed file with its own hash.
- **Exact reproduction**: provider sampling is not controllable (no temperature on current Anthropic models), so a re-run is a *stability replicate*, not a bit-identical replay. Bit-identical replay of every published number is possible without any API from the archived outputs (`archive/`, `data/worked_profiles/*/`), which is the reproducibility claim the paper makes.

## Versioning

Each contract/schema version gets its own exported prompt set; the manifests of archived runs name the hashes. Changing a prompt means changing the contract or the script, exporting again, and committing both with the test passing.
