## What broke and was fixed in the runner

- OpenAI enqueued-token limit for gpt-6.2-sol on this account: 1,350,000 tokens in flight. Parallel batches were refused
  whole (`token_limit_exceeded`) and the runner counted each as a transient attempt. Fixed: such a batch is recorded as
  refused, not as an attempt, and `--max-enqueued-tokens` keeps the input in flight under the limit (1,200,000 used).
  The first Sol runs (`DEV_EX_sol62`, `DEV_L1S_sol62`) are kept as records; the repeats are `*_sol62b`.
- DeepSeek sub-cap overshoot, above.

## Proposals (for MB; nothing changed in the prompts)

1. Extraction requests of at most about 60,000 characters (`--max-chars 60000`; owned page ranges with a context page, as
   built) for every model. This removes both failures above; it adds requests (about 223 → 400) but not text.
2. Read `null` as `n/d` for every field whose allowed values include `n/d` (`legal_state`, `referenced_law_state`, as for
   `modality` on 23 Nov).
3. Talk L1 by page in production: it agrees with the single-unit run on 97 % of units for Claude and Sol, raises the
   three-model agreement, and costs about 40 % less.
4. Before production, re-run only the 8 failed extraction requests split by proposal 1 (about 3 USD) to see that they pass.
