## Code and tests

1. **Confirmed with correction — 19 tests passed.** I ran `python -m pytest -q` from the repository root with Python 3.12.14 and pytest 9.2.0. All 19 passed in 0.89 s. The brief reports 16. The extraction tests use the v1.1 schema. In a separate probe, validating a recognized cell with the supplied v2 draft schema raised `KeyError: 'claim_status'`. Add a v2 extraction-to-derivation test before calling v2 executable. A CI workflow is present. A successful hosted CI run is **not verifiable from the pack**. Evidence: brief line 9, `tests/test_extract_validation.py` lines 6–35, `scripts/extraction/extract_api.py` lines 97–117, `schema/cells_v2_DRAFT.json` status fields, `.github/workflows/verify.yml`.

2. **Not confirmed — rule C is only partly implemented.** Yes and no pass the same gate. But a documented “no” with `decision_status=rejected` and `implementation_status=operational` returned admissible. The gate does not inspect the official source layer, decisive qualifiers, supersession, or an independent conflict flag. A conflict encoded in `evidence_state` does fail. A legacy `claim_status` takes precedence even when blank. The gate also excludes eligible categorical values. For posture, the four excluded types and all unlocated quotes contribute nothing, as specified. The ladder works on the schema’s `type` field, but feeding it the contract’s `statement_type` field turned an endorsed, located architectural claim into P0. Align the field names and enforce the full eligibility rules before deriving outcomes. Evidence: contract lines 49–51, 68–80, 88, 104–113, `scripts/derive.py` lines 16–23, 69–92, `schema/cells_v2_DRAFT.json` → `statement_columns`.

3. **Confirmed with correction — full-string matching works, but the ordering loses a valid span.** A matching prefix with a changed suffix cannot earn an exact match. A quote found only on another page cannot earn `exact_page` for a valid integral locator. Duplicate text can match on both pages. I tested a quote spanning pages 1–2 that also appeared whole on page 3. Citing page 1 returned `elsewhere_in_doc`. Test a genuine boundary crossing at the cited page before accepting a remote duplicate. Also reject fractional locators instead of silently truncating them with `int(float(...))`. Evidence: `scripts/extraction/verify_quotes.py` lines 38–56, 63–69 and `tests/test_verify_quotes.py` lines 16–24.

4. **Confirmed with correction — a recorded failure is caught, omitted coverage passes.** An explicit failed or incomplete processing state makes the comparison INVALID. The extractor normally propagates a stage-one failure. But the comparator never reads the manifests. Comparing a header-only fill to the complete Norway fill printed `VALID {'missing': 17}`. Missing cells, silently omitted documents and different source sets can therefore pass. Require matching expected document IDs and text hashes, completed stages and one row per expected cell. Return a failing exit status when those checks fail. Evidence: `scripts/extraction/compare_modes.py` lines 20–47, `extract_api.py` lines 189–225, `tests/test_compare_modes.py` lines 16–30.

5. **Confirmed with correction — the two committed aggregates contain no named project result.** Both JSONs under `data/census/` contain counts, run metadata and a sealed-file digest. The posture release separately includes the two exposed development projects. Sealing depends on the operator: the census prints project and category to stdout, the survey prints a document’s statement count, and both accept arbitrary output paths. The release script trusts its command-line project list. Enforce an off-repository sealed destination, suppress identifying logs and check a dated exposure allowlist. ## Methodological judgements

17. **Confirmed with correction — P0–P3 is a partition of eligible, located claims under the written priority rule.** Its labels overstate what some levels establish. A rejected-only architectural claim produces P2 “considered/tested”. All-invalid quotations or an incomplete search can produce P0 “silent”. Staff research can set a level if supplied, despite its exclusion in the contract. G2 and G8 can read as commitments in the interface, and the G ranking ignores the separate implementation axis. The separation from Y preserves the strict definition in principle. Keep that separation in the exports. Show “statement found”, both status axes, basis, date and locator. Separate incomplete coverage from a completed search. Require eligible authority, scope and current design for a P3 called a commitment. Evidence: contract §6b.1–6b.5, `derive.py` lines 74–103, `site.js` lines 98–105.

18. **Confirmed with correction — make measurement and data the core.** A single unvalidated census supplies too few plausible strict outcomes for classified H2. The permissive view mixes proposals, tests and decisions. Any association there answers a different question. A defensible alternative is to omit H2 and publish a status-by-evidence table, missingness bounds and the count of cases that lose determinate values under rule C. If H2 remains exploratory, require human-coded outcomes, comparable statuses, covariate completeness and adequate minority counts before estimating it. Remove the conflicting classified-H2 language in contract §8. F1-only census data cannot establish the brief’s prediction that F9/F10 are rarer. Evidence: brief lines 28–37, contract lines 145–148, ADR-001 rows E5 and F2–F9.

19. **Confirmed with correction — I found no released, named survey value for an unexposed project.** The website, both aggregate JSONs, design memo examples (lines 81–88) and all **14** supplied commit subjects pass that check. The prompt says 12 commits. Earlier v1 results and screening evidence were already seen, as disclosed in `EXPOSURE_LEDGER.md` lines 13–25. ## Five most serious problems, ranked

1. **The brief misreports the UK primary outcomes.** Its own derivation changes both to undetermined in two-stage. This affects the consultation decision directly (11, 20).
2. **The executable instrument does not enforce the proposed contract.** Rule C accepts disallowed records and v2 extraction validation fails on the draft schema. Passing tests give no end-to-end v2 assurance (1–2, 17).
3. **The sampling domain is miscounted and one source was misclassified.** Freezing the ledger as written would distort eligibility and prevent a defensible account of who the validation covers (13, 21).
4. **The deposit permission claim exceeds the recorded grants.** Two reports alone disprove the blanket clearance for 69 full files (15).
5. **The headline coverage estimates outrun the aggregate evidence.** “5–8 determinable” includes systems with no documented arrangement. The posture memo’s 41 architectural projects disagrees with its own ladder, and the released tables cannot settle the difference (8–9).

**Overall judgement.** Proceed with a measurement-and-data paper and defer the instrument freeze. The frame counts, prompt hashes, mode-comparison counts and UK page offsets reproduce. The pack does not establish a validated cross-country commitment count, equivalent outcomes across modes, or the claimed language domain. Correct the Friday brief, make the v2 schema and eligibility rules executable together, and freeze a source-checked language and release manifest before the blind draw. Human source coding can establish how often the official documentation answers F1 and why the remaining projects are indeterminate.
