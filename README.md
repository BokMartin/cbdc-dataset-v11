# CBDC Dataset — v11 (work in progress)

Open dataset and working paper on **documented privacy and identifiability design in retail central bank digital currency (CBDC) projects**, built only from official central-bank and government documents.

> **Status (18 Oct 2026): work in progress.** Corpus and core selection are frozen; the measurement contract is at v1.1; the extraction pipeline is built; two development profiles (Norway, United Kingdom) are coded with verified quotes. **Every other cell value on the website is mock data** generated by `scripts/site/build_site_data.py` to show the finished product. Nothing here is a finding yet.

Paper: *Institutional Determinants of Privacy Design in Central Bank Digital Currencies* (Bok & Stroukal). Previous release (v1, vocabulary-based purpose categories): [cbdcdataset.org](https://cbdcdataset.org).

## What v11 measures

For each project, a small matrix of design questions answered from its own official documents under a written [measurement contract](docs/MEASUREMENT_CONTRACT_v1_1_2026-10-18.md). Each cell = value · evidence state · commitment status (option / adopted / tested / operational) · document + page + verbatim quote · date.

| Layer | Cells | Use |
|---|---|---|
| Architecture | F1 central bank can link online payments to a person · F2 the PSP can · F4 private offline mode adopted | deterministic type A0 … C1 |
| Further design | F7 low-identification route · F8 onboarding identity · F9 targeted re-identification · F10 programmable restrictions · F3 documented lawful-access route · F12 ledger technology | descriptive; Y₁ = F1, Y₃ = F7 |
| Purpose | F11 declared objectives (6 non-exclusive flags + primary status) | descriptive |
| Time | per-cell history (year, document, value, status) | change map |

## Repository layout

```
site/                 static website (GitHub Pages): map with year slider, features & types, method & progress, data
  assets/data.json    generated — real registry/status/development profiles + MOCK cell values
scripts/site/build_site_data.py   regenerates data.json (run from repo root; stdlib + pycountry)
scripts/extraction/   extract_api.py (reproducible API extraction, single and two-stage modes, full logging)
                      verify_quotes.py (mechanical check that each quote is on its cited page)
docs/                 MEASUREMENT_CONTRACT_v1_1, PREDICTIONS_v2_2 (draft for registration), CORE_RUBRIC, corpus changelog
data/registry/        REGISTRY_v2_2.csv (391 documents, SHA-256, source URLs, core flags), CORE_V1_FREEZE.json
data/jurisdictions/   official project status, 85 jurisdictions, with sources
data/worked_profiles/ Norway & UK development fills (contract v1.1) + run manifests + Norway history
METHOD.md             progress and step-by-step plan (for the supervisor); PROGRESS_cs.md — Czech summary
```

PDFs are not redistributed; every registry row carries its official URL and hash.

## View the site locally

```
cd site && python3 -m http.server 8000     # then open http://localhost:8000
```

On GitHub, enable Pages for the `site/` folder (Settings → Pages → Deploy from branch → `/site`). No build step.

## Reproduce an extraction run

```
export ANTHROPIC_API_KEY=...        # or OPENAI_API_KEY with --provider openai
python3 scripts/extraction/extract_api.py --jur NO --model claude-opus-5-5 --mode both \
    --indir <folder with DOCS.csv and texts/docNN.txt> --contract docs/MEASUREMENT_CONTRACT_v1_1_2026-10-18.md --outroot runs
python3 -I scripts/extraction/verify_quotes.py runs/<run>/FILL.csv <folder>
```

The text folder (page-delimited extracts of the core PDFs) is not in this repository; it is produced from the registered documents with `pdftotext -layout` and OCR for scans.
